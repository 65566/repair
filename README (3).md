# تعليمات تركيب موقع متابعة صيانة الأجهزة

الموقع فيه ٥ ملفات:
- `index.html` → الصفحة الرئيسية العامة: تعريف بالمركز، الخدمات، عينة من الشغل، العنوان
- `portal.html` → صفحة خاصة للعميل: يدخل برقم هاتفه + كود أي جهاز ليه عندك (للتأكيد)، وبعدها يشوف كل أجهزته
- `admin.html` → لوحة الموظفين (محمية بكلمة سر بسيطة): تسجيل جديد، تعديل/فواتير، العملاء
- `admin-demo.html` → نسخة تجربة بدون أي إعداد (بيانات محلية في المتصفح بس) — للتجربة فقط
- `firebase-config.js` → إعدادات الاتصال بقاعدة البيانات (لازم تعبيها بنفسك)

رابط `admin.html` مش مربوط من الصفحة الرئيسية — شاركه مع فريقك فقط.

## تخزين الصور: Cloudinary بدل Firebase Storage
عشان نتجنب شرط تفعيل خطة Blaze والبطاقة البنكية، بيانات الأجهزة (النصوص) متخزنة في **Firestore** (مجاني تمامًا)، والصور بس متخزنة في **Cloudinary** (خدمة مجانية منفصلة، مش محتاجة بطاقة بنكية خالص للتسجيل والاستخدام في حجم شغلك).

### إعداد Cloudinary
1. روح على https://cloudinary.com وسجل حساب مجاني (بس إيميل، من غير كارت).
2. من الصفحة الرئيسية للوحة التحكم (Dashboard)، هتلاقي **Cloud name** مكتوب فوق — انسخه.
3. من القائمة الجانبية: **Settings** (الترس) → تبويب **Upload** → انزل لـ **Upload presets** → دوس **Add upload preset**.
4. غيّر **Signing Mode** من Signed لـ **Unsigned** → احفظ (Save)، وانسخ اسم البريست اللي ظهر.
5. افتح `admin.html`، ودور على السطرين دول في أول السكريبت:
   ```js
   const CLOUDINARY_CLOUD_NAME = "ضع_اسم_الحساب_هنا";
   const CLOUDINARY_UPLOAD_PRESET = "ضع_اسم_البريست_هنا";
   ```
   استبدلهم بالقيم اللي نسختها.

الخطة المجانية من Cloudinary فيها حوالي ٢٥ جيجا تخزين + ٢٥ جيجا نقل بيانات شهريًا — تغطي حجم شغلك بسهولة شديدة.

## تعديل محتوى الصفحة الرئيسية
قائمة الخدمات وصناديق "عينة من شغلنا" في `index.html` محتوى مبدئي مكتوب عليه علامة ✏️ — افتح الملف وعدّل النصوص، واستبدل صناديق الصور برابط صورك الحقيقية لما تجهزها.

## ملاحظة أمان بخصوص صفحة العميل (portal.html)
التحقق بالتليفون + الكود ده حماية بسيطة (مش تسجيل دخول حقيقي بكلمة سر)، كافية عمليًا لأن الكود شبه سري ومش حد هيعرفه غير العميل.

## تسجيل دخول الموظفين (يوزر + باسورد)
بدل كلمة سر واحدة مشتركة، دلوقتي كل موظف له اسم مستخدم وكلمة سر خاصة بيه، متخزنين في Firestore (كولكشن `users`)، وتديرهم من تبويب **"المستخدمون"** جوه لوحة الإدارة (إضافة، حذف، تغيير كلمة السر).

⚠️ **أول حساب لازم تعمله بنفسك يدويًا** (عشان النظام لسه مفيش فيه حد مسجل دخول يقدر يضيف مستخدم من الصفحة نفسها):
1. من Firebase Console → **Firestore Database** → تبويب **Data** → **Start collection**.
2. اسم الكولكشن: `users`
3. Document ID: اسم المستخدم نفسه (مثلاً `ahmed`)
4. أضف حقلين (Fields):
   - `username` (string) = نفس الاسم (`ahmed`)
   - `password` (string) = كلمة السر اللي تحبها
5. احفظ (Save).

بعد كده افتح `admin.html`، اختار المستخدم ده من القائمة، واكتب كلمة السر، وتقدر من تبويب "المستخدمون" تضيف باقي الموظفين من غير ما ترجع لـFirebase تاني.

⚠️ ملاحظة أمان: كلمات السر متخزنة كنص عادي (مش مشفّرة) في Firestore، وده مقبول عمليًا بما إن رابط admin.html سري بينك وبين فريقك. لو حد عرف الرابط وفتح Developer Tools ممكن يقرا كل أسماء المستخدمين وكلمات سرهم — فحافظ على الرابط ده سري زي ما اتفقنا قبل كده.

## الخطوة ١: عمل مشروع Firebase (مجاني بالكامل، مفيش داعي لخطة Blaze خالص)
1. روح على https://console.firebase.google.com وسجل دخول بحساب Google.
2. اعمل مشروع جديد (Add project) وسمّيه مثلاً "repair-center".
3. من القائمة الجانبية فعّل:
   - **Firestore Database** → Create database → اختار وضع الإنتاج (Production mode).
   - **Authentication** → Get started → من تبويب Sign-in method فعّل طريقة **Anonymous** بس (زرار Enable، مفيش بيانات تدخلها). ده مطلوب عشان Firestore Rules تعرف تفرّق بين زيارة عادية وموظف داخل من admin.html.
   - **مفيش داعي تلمس Storage خالص** — بنستخدم Cloudinary بدالها زي فوق.

## الخطوة ٢: نسخ إعدادات المشروع
1. من Project settings (أيقونة الترس) → Your apps → اختار Web (</>) واديله اسم.
2. هيديك كود فيه `apiKey`, `authDomain`, إلخ.
3. انسخهم داخل ملف `firebase-config.js` مكان "ضع_القيمة_هنا".

## الخطوة ٣: ضبط صلاحيات القراءة/الكتابة (Firestore Rules فقط)
في Firestore → Rules، استبدل المحتوى بده:
```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /devices/{code} {
      allow read: if true;
      allow write: if request.auth != null;
    }
    match /customers/{phone} {
      allow read: if true;
      allow write: if request.auth != null;
    }
    match /backups/{id} {
      allow read, write: if request.auth != null;
    }
    match /meta/{id} {
      allow read: if true;
      allow write: if request.auth != null;
    }
    match /ledger/{id} {
      allow read, write: if request.auth != null;
    }
    match /users/{username} {
      allow read: if true;
      allow write: if request.auth != null;
    }
  }
}
```
معناها: أي حد يقدر يقرأ بيانات جهاز لو عنده كوده (عشان العميل يستخدم portal.html من غير تسجيل دخول رسمي)، لكن الكتابة/التعديل مقصورة على الموظفين اللي داخلين admin.html بيوزر وباسورد صحيحين.

## الخطوة ٤: نشر الموقع (Hosting مجاني)
1. حمّل Node.js من https://nodejs.org (لو مش مثبت عندك).
2. افتح الطرفية (Terminal / cmd) جوه فولدر الموقع وشغل:
   ```
   npm install -g firebase-tools
   firebase login
   firebase init hosting
   ```
   - اختار المشروع اللي عملته.
   - public directory: اكتب "." (النقطة، يعني الفولدر الحالي).
   - Single-page app: لا (No).
3. بعدين شغل:
   ```
   firebase deploy
   ```
4. هيديك رابط زي `https://repair-center.web.app` — ده رابط موقعك الحقيقي، أي حد يفتحه من غير أي حساب.

## التحديثات الجديدة في admin.html
- **تسجيل جديد**: الجدول بقى أفقي (كل جهاز سطر واحد)، كل خانة (عطل/تشخيص/صور/ملاحظات) بتفتح قائمة اختيار منبثقة بدل ما تكون ظاهرة طول الوقت. الكود بقى بصيغة (يوم+شهر+رقم تسلسلي يبدأ من صفر) — مثلاً أول جهاز يوم 30/9 كوده "3090". حفظ عميل بيحفظه للملء التلقائي في المرات الجايه (اكتب الاسم أو التليفون ويكمل الباقي لوحده).
- **الفواتير**: قائمة بكل الأجهزة المسجلة مع زرار تعديل لكل واحد.
- **العملاء**: الدوس على عميل بيفتح صفحة فيها كل فواتيره، المطلوب منه (أجل)، رصيده (credit)، وزرار "تسجيل دفعة".
- **مدفوعات**: مدخل سريع بالتليفون يوديك على نفس صفحة حساب العميل وتسجيل الدفعة.
- **دفعة جزئية**: تقدر تدفع فاتورة كاملة، جهاز أو جهازين محددين، أو جزء من المبلغ — والباقي يفضل مطلوب (أجل) تلقائيًا، وأي زيادة في الدفع تتحول لرصيد (credit) للعميل.
- **مراجعات**: قائمة كل الأجهزة، فلترة بالتاريخ أو بالكود، زرار تفاصيل (قراءة فقط) وزرار "مرتجع" اللي بيخصم قيمة المدفوع من الدخل ويضيفها لرصيد العميل.
- **قاعدة البيانات**: صفحة لإضافة/حذف الأعطال والتشخيصات بنفسك من غير ما تفتح الكود — بتتحفظ في Firebase وتتحمل تلقائي في كل الصفحات.
- **تقارير**: محمية بكلمة سر منفصلة (2007)، بتعرض عدد الأجهزة في كل حالة + صافي الدخل (بعد خصم المرتجعات).
- **المستخدمون**: تسجيل الدخول بقى باختيار يوزر + كلمة سر خاصة به (بدل كلمة سر واحدة مشتركة)، وتبويب جديد لإضافة/حذف/تغيير كلمة سر المستخدمين.

⚠️ ملحوظة: نسخة `admin-demo.html` (التجربة بدون إعداد) لسه بالشكل القديم قبل هذه التحديثات — قولّي لو عايزني أحدّثها كمان.

## صفحة الإعدادات (في admin.html)
- **حالة الاتصال**: مؤشرين لونيين فوق الصفحة — واحد للداتا (Firestore) وواحد للصور (Cloudinary)، أخضر = متصل، أحمر = فيه مشكلة.
- **نسخة احتياطية يدوية**: تنزيل كل بيانات العملاء والأجهزة كملف JSON على جهازك، أو استعادتها من ملف سابق.
- **نسخ تلقائية على Firebase**: بتاخد نسخة تلقائية أول ما تدخل اللوحة كل يوم، وتقدر كمان تاخد نسخة يدوية وترجع لأي نسخة سابقة من نفس الصفحة.

## خريطة الاستخدام
- `.../` (الرئيسية) → للعامة: تعريف بالمركز، الخدمات، العنوان — تحطه على كارت المركز والفواتير.
- `.../portal.html` → للعميل: يدخل تليفونه + كود جهاز عنده، يشوف كل أجهزته.
- `.../admin.html` → للموظفين فقط: دخول بيوزر وباسورد، تسجيل جديد، تعديل/فواتير، العملاء، المستخدمون.

## ملاحظات
- الخطة المجانية (Spark) لـFirestore بتغطي بسهولة ١٠٠-٢٠٠ جهاز شهريًا، ومعاها Cloudinary المجاني للصور — يعني المشروع كله ممكن يشتغل من غير ما تدفع أي فلوس أو تحط بطاقة بنكية في أي حتة.
- لو حبيت أضيف: إشعارات واتساب تلقائية، أو صفحة موافقة العميل على السعر، قولّي.
